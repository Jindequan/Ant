## 一、你的原始需求（原话直读， Minimal 推导）

你要一个自部署的应用：把多家 AI 服务商账号的额度管起来。

1. **在界面里配置**：各类 provider 的各类资源；账户按真实商业事实录入（账户名下有真实的套餐/资源包）——**不是**让用户填内部记账字段，也**不是**把账户当成"订阅"（这两条是两次否决确立的）。
2. **组池**：不同类型的资源组成逻辑资源池。
3. **优先级**：池内资源按优先级消费；优先级**手动调整**。
4. **调度在服务端**：切换、派发、故障转移由服务端做。
5. **后端用 Go**，用好语言特性做性能。
6. **免费基础设施**：不引入付费的基础设施服务。
7. **核心最重要、且要可扩展**：把 Ant 的核心建到最强；将来会接入越来越多的 provider、资源类型和用量计算。
8. **顺序**：先做资源配置（provider → 账户 → 套餐/包 → 资源/限额 → 池 → 优先级），消费执行是下一步。
9. **首个业务域 = AI 调用**；**单机部署**。
10. **内部 Hooks**：核心在显式的生命周期边界上支持灵活的类型化扩展（不动态加载外部代码）。
11. 已给 provider 候选三家：DeepSeek API、阿里云 Token Plan（含免费额度）、火山方舟 Coding Plan。（执行者按官方条款取证后裁定：后两者套餐禁止后端调用、不可受理，标准 API 为候选——此为执行者结论，供参考，可复查。）
